# Contributing / Как внести вклад

Спасибо за интерес к улучшению шаблонов! Это учебный проект разработан на кафедре ЭВМ, БГУИР для курса "Жизненный цикл разработки ПО" в 2026 году и мы приветствуем:

- исправления опечаток и неточностей
- улучшения формулировок подсказок (💬, ➥, 💡)
- добавление новых разделов, соответствующих современным стандартам

## Принципы

1. **Соответствие стандартам.** Любое изменение должно быть совместимо с IEEE 830, ISO/IEC/IEEE 29148, IEEE 1016, ISO/IEC/IEEE 42010 или MADR 4.0.
2. **Двуязычность.** Изменения должны вноситься и в английскую, и в русскую версию шаблона.
3. **Сохранение терминологии.** Не переводите устоявшиеся термины: SRS, SDD, ADR, MADR, Viewpoint, View.
4. **Обратная совместимость.** Старайтесь не ломать структуру существующих разделов.

## Процесс

1. Форкните репозиторий.
2. Создайте ветку: `git checkout -b fix/название`.
3. Внесите изменения.
4. Создайте Pull Request с описанием изменений.

## Как использовать этот репозиторий в учебном процессе

### Для студентов

- Клонируйте репозиторий в начале семестра.
- Для каждого лабораторного проекта создавайте собственную ветку документации.
- Следуйте подсказкам (💬, ➥, 💡) в полных шаблонах.

### Для преподавателей

- Шаблоны служат единым стандартом оформления работ.
- Критерии оценки могут быть привязаны к разделам шаблонов.
- ADR позволяет оценивать не только результат, но и качество принятых решений.

### Для команд разработки

- Репозиторий можно форкнуть как основу корпоративного стандарта документации.
- Шаблоны совместимы с pandoc (PDF/HTML), MkDocs, Docusaurus.
- ADR интегрируется с инструментами: adr-tools, log4brains.
